Clear Context workflow diagrams

Diagrams 01-03, 07 and 13-16 describe working application code: 13 is the opt-in text research flow, 14 images, 15 links and 16 budget continuations. Diagrams 04-06 describe proposals (05 is now mostly implemented as 14, and 06 as 03); 08-09 show experimental runners; 10-12 show evaluation-workspace stages that the application flow reuses or does not select. Examples are explanatory, not measured inference results.

  1. Text request: from browser to saved report IMPLEMENTED

    The API saves queued state before responding. Background processing starts after the response. One successful extraction makes one Meta call. With research disabled, internal evaluation and report validation do not call Meta; with RESEARCH_ENABLED=true, evaluation runs the bounded research flow shown in diagram 13. GET results groups status, steps, and report polling; it is not a single endpoint. Message spacing is illustrative, not latency. Failure paths are detailed in diagram 02.

  2. Selecting claims is not checking their truth IMPLEMENTED

    V2 validates exact quotes and source/context offsets while storing the independent statement as a model interpretation. The default per-call completion budget is 4,096 tokens. A saturated or truncated range can split; invalid or deferred ranges remain partial. V1 remains a legacy single-call contract. Literal anchoring does not verify statement meaning or truth. See diagram 07 for bounded chunk processing.

  3. What happens to an image or video today IMPLEMENTED

    Clipboard, file picker and drag and drop share validation; files are checked by signature, not name. Images go through the image checks in diagram 14 in Meta mode; preview mode stores them without analysis. Videos up to 50 MB and 10 minutes are checked in Meta mode: speech is transcribed with timestamps, a Muse model reads the frames with that transcript, and three frames are searched like images; larger videos are stored and reported as not analyzed. A video the browser cannot decode gets a WebM copy for playback. No AI-generation detector is integrated.

  6. Video claims need timestamps and coverage limits PROPOSAL, MOSTLY IMPLEMENTED IN 03

    A silent clip takes only the frame branch. If transcription or decoding fails, preserve that gap. Compare claims with external sources and the relevant interval. Sampling can miss edits or events; neither a few real frames nor a detector score proves the entire clip. Frame sampling, speech transcription and timestamps are now implemented (diagram 03); this diagram is kept as the original proposal. AI detection is not implemented.

  7. Claim coverage without an eight-claim ceiling IMPLEMENTED

    The default target budget is 600 Unicode characters, not tokens. Context includes document-head, previous, and next windows, each bounded to 600 characters. A response can hold 24 claims by default; capacity is not a document-wide limit. Capacity or truncation can split a target. Minimum-size, invalid, timeout, and budget cases remain partial. All source spans are anchored literally; statements remain model interpretations. No external evidence is retrieved. The figure groups error paths for readability.

  8. Method B: LangExtract claim extraction EXPERIMENTAL

    Experimental B uses LangExtract to construct and parse a one-call request. The current system-role adapter moves the exact rules prefix to system; historical runs used user. The model writes statements and group labels; Python checks the schema and literal source quote. Empty arrays may be structurally valid. This is an experimental runner, not the deployed application pipeline.

  9. Method D: direct claim extraction EXPERIMENTAL

    Experimental D sends a direct schema-constrained request to Meta. Rules are in system, and source with supplied context is in user. The model writes statements and group labels; Pydantic and literal matching validate structure and provenance. Empty arrays may be structurally valid. This is an experimental runner, not the deployed application pipeline.

  13. From text to source-backed details IMPLEMENTED / OPT-IN

    Planner v7 marks opinions and author-only experiences not_checkable and plans the main claims first. Every readable page that search finds is read (modes differ by search count); results Tavily scores below SEARCH_MIN_SCORE (0.30) are skipped. Pages are read as Markdown reduced to text. The v5 judge receives each passage's source type, and a passage that only repeats the claim is not support. Each need is assessed independently; a need left insufficient gets one follow-up search. Unreadable sources and unfinished steps remain limitations; the overall claim remains unresolved when coverage is unknown. Budget-limited needs can be continued (diagram 16).

  14. Checking a photo and its caption IMPLEMENTED

    Muse transcribes visible text and marks which parts are statements; only statements, not signs, labels or date stamps, are extracted as claims. Caption checks compare what the caption says about the picture with visible details and are labelled a model visual assessment. SerpApi Google Lens returns same-image matches with the date Lens shows (earliest first); Bing reverse image search, queried with a Google-hosted copy Lens found, adds direct page links. Google Fact Check Tools image search uses the same copy, never the upload, and text search uses the caption. Research reads fact checks and other matching pages alternately on its own small budget, and the planner gets observations and matching page titles as context. Google redirect links that show a verification page are not read. Reverse image search runs only in Meta mode with REVERSE_IMAGE_PROVIDER set.

  15. Checking a linked page IMPLEMENTED

    fetch_links reads up to three links in Meta mode through Tavily Extract; preview mode lists them as not opened. Only the first 3,000 characters are checked, since a whole article produced more claims than one research budget can assess. A publication date is kept only when a Tavily news search returns the exact page; it is never guessed from page text. The main image is downloaded from a public HTTPS host, with redirects re-checked and the connection pinned to the checked address, then analysed like an upload. Research never reads the checked page as its own evidence. Unreadable links (often social posts) are reported with advice to paste the text or attach a screenshot.

  16. When the research budget runs out IMPLEMENTED

    Planner v7 marks opinions, value judgments and experiences only the author could know as not_checkable; they are listed but never searched or judged. Under a tight budget it plans the headline and main claims first. Each report saves a research summary; budget-limited counts the needs the planner deferred or the judgment call budget did not reach. The notice offers Run again in Deep (same text and uploads, new report) or Research remaining details: a new investigation that copies settled claims, findings, evidence and sources under new IDs and researches only budget-limited claims, starting at evaluate_evidence and passing through merge_continuation. Images and links stay in the earlier report, which is linked.
